La Capa de Internet

IPv4, encabezado IP, TTL, MTU, fragmentacion, tablas de ruteo, algoritmos intra-AS e inter-AS, ICMP y DHCP.

Disenada para repasar teoria, visualizar el flujo de paquetes y practicar preguntas tipicas de certamen.

Parte 1 · Vision general

1 Que hace la capa de Internet

La capa de Internet transmite paquetes desde un host origen hacia un host destino usando routers como intermediarios. Su servicio es no orientado a conexion, no mantiene estado por flujo y delega confiabilidad, retransmision y recuperacion de perdidas a la capa superior, tipicamente transporte.

Direcciones IP

Identifican de forma logica al emisor y al destino dentro de la red.

Routers

Toman decisiones salto a salto consultando tablas de ruteo.

Abstraccion

Oculta la tecnologia subyacente: Ethernet, Wi-Fi, fibra u otros medios.

Best effort

Puede haber perdidas, reordenamiento o rutas diferentes para paquetes consecutivos.

2 Idea clave para no confundir capas

La capa de Internet si hace

  • • Direccionamiento logico con IP.
  • • Encapsular datos de transporte dentro de datagramas IP.
  • • Elegir proximo salto mediante ruteo.
  • • Control basico con TTL e ICMP.
  • • Fragmentar en IPv4 si el MTU lo obliga.

La capa de Internet no hace

  • • Garantizar entrega extremo a extremo.
  • • Reordenar segmentos perdidos o duplicados.
  • • Mantener una conexion abierta como TCP.
  • • Saber que aplicacion final usa los datos; eso lo ve transporte.
  • • Corregir errores de aplicacion.

Parte 2 · IPv4 en detalle

3 Formato del datagrama IPv4

El datagrama IPv4 tiene un header minimo de 20 bytes y luego los datos transportados. Pasa el cursor sobre cada campo para revisar su funcion practica.

Bit 0Bit 15 · Bit 16Bit 31
Version 4
Version
Indica la version del protocolo IP. Vale 4 para IPv4 y 6 para IPv6.
IHL 4
IHL — Internet Header Length
Tamano del header en palabras de 32 bits. Minimo 5 (= 20 bytes). Si hay opciones puede llegar a 15 (= 60 bytes).
DSCP / ECN 8
DSCP / ECN
DSCP permite trato diferenciado de trafico (QoS). ECN senaliza congestion sin descartar el paquete.
Total Length 16
Total Length
Tamano completo del datagrama: header + datos. Maximo teorico 65 535 bytes. El receptor usa este campo para saber cuantos bytes leer.
Identification 16
Identification
Numero unico asignado por el emisor. Todos los fragmentos del mismo datagrama original comparten este valor para poder reagruparse en el destino.
Flags 3
Flags
Bit 0: reservado (0). Bit 1: DF (Don't Fragment) — si vale 1 el router descarta el paquete si no cabe y envia ICMP. Bit 2: MF (More Fragments) — 1 indica que vienen mas fragmentos.
Fragment Offset 13
Fragment Offset
Posicion de los datos de este fragmento dentro del datagrama original, medida en bloques de 8 bytes. Primer fragmento = 0.
TTL 8
TTL — Time To Live
Cada router decrementa este valor en 1. Si llega a 0 el paquete se descarta y el router envia ICMP Time Exceeded al origen. Evita loops infinitos.
Protocol 8
Protocol
Identifica el protocolo en el payload: 1 = ICMP, 6 = TCP, 17 = UDP, 89 = OSPF. El receptor usa este valor para demultiplexar.
Header Checksum 16
Header Checksum
Suma en complemento a 1 del header IP. Solo cubre el header, no los datos. Cada router debe recalcularlo al decrementar el TTL.
Source Address 32
Source Address
Direccion IPv4 del host que origina el datagrama. No cambia durante el transito (salvo con NAT).
Destination Address 32
Destination Address
Direccion IPv4 del host destino final. Los routers la consultan para decidir el siguiente salto. No cambia durante el transito.
Options + Padding (opcional, raramente usado)
Options
Campo opcional que agranda el header. Incluye opciones como registro de ruta, timestamp o seguridad. Hace crecer IHL mas alla de 5.
PAYLOAD · TCP / UDP / ICMP / OTROS

Dato de prueba clasico

Si el campo Protocol vale 6, el payload es TCP. Si vale 17, es UDP. Si vale 1, es ICMP. Este campo permite a la capa IP demultiplexar hacia el protocolo correcto.

Punto de certamen

El checksum IP protege solo el header, no los datos de aplicacion. TCP y UDP calculan su propio checksum sobre los datos. Esto es deliberado: mantiene IP simple.

Error frecuente

Confundir TTL con tiempo real en segundos. Originalmente era en segundos, pero en la practica funciona como contador de saltos: cada router resta 1, independiente del tiempo.

4 TTL y prevencion de loops

TTL evita que un paquete quede circulando indefinidamente si hay un loop de ruteo. Cada router reduce el valor en 1 y, cuando llega a cero, descarta el paquete y avisa al origen con ICMP Time Exceeded.

Host AR1R2R3Destino
TTL=4
TTL=3
TTL=2
TTL=1
TTL=0 Drop
Valor tipico: sistemas operativos modernos envian paquetes con TTL=64 (Linux/macOS) o TTL=128 (Windows). Un traceroute permite estimar el TTL inicial del host remoto por la formula: TTL_inicial - TTL_recibido = saltos.

Relacion con traceroute

Traceroute envia paquetes con TTL=1, luego TTL=2, y asi sucesivamente. Cada router donde el TTL expira responde con ICMP Time Exceeded, revelando la ruta salto a salto.

TTL=1 responde Router 1 TTL=2 responde Router 2 TTL=3 responde Router 3 ... TTL=n responde el destino

Cada linea del output incluye la IP del router y el RTT medido. Los asteriscos (*) indican que ese router no respondio ICMP en el tiempo de espera.

5 MTU y fragmentacion

El MTU es el tamano maximo de paquete que un enlace puede transportar. Si un router debe enviar un datagrama mas grande que el MTU del proximo salto, en IPv4 puede fragmentarlo, salvo que el bit DF este activado.

Sin fragmentacion

Con fragmentacion

DF = 1

No se puede fragmentar. Si el paquete no cabe en el MTU, el router lo descarta y envia ICMP Fragmentation Needed al origen. Usado en Path MTU Discovery.

MF = 1

Significa que aun faltan fragmentos por llegar. Solo el ultimo fragmento del datagrama lleva MF = 0. Sin el ultimo fragmento, el destino no puede reensamblar.

Offset

Se expresa en bloques de 8 bytes, por eso el tamano util de cada fragmento (excepto el ultimo) debe ser multiplo de 8. Permite al destino calcular la posicion exacta de cada fragmento.

Procedimiento sistematico para ejercicios de fragmentacion

1. Datos del fragmento = MTU - 20 (header IP minimo) 2. Redondear ese tamano hacia abajo al multiplo de 8 mas cercano 3. Calcular cuantos fragmentos se necesitan: ceil(datos_totales / datos_por_frag) 4. Asignar el mismo Identification a todos los fragmentos 5. Fragment Offset[i] = suma de datos de los fragmentos anteriores / 8 6. MF = 1 en todos los fragmentos excepto el ultimo (MF = 0)

Parte 3 · Ruteo y escalabilidad

6 Tabla de ruteo y regla del prefijo mas largo

Un router decide el siguiente salto consultando su tabla de ruteo. Si varias entradas coinciden con la direccion destino, se elige la de prefijo mas largo, es decir, la mas especifica.

Destino Gateway Mascara Flags Interfaz
30.0.0.00.0.0.0255.0.0.0Ueth1
30.3.0.020.1.2.3255.255.0.0UGeth0
30.1.2.320.1.0.1255.255.255.255UGHeth0
default30.0.0.10.0.0.0UGeth1

La fila resaltada tiene mascara /32 (host especifico). Si el destino es 30.1.2.3, aunque la primera entrada tambien coincide, se elige esta por ser el prefijo mas largo.

U = la ruta esta activa y el enlace esta up.
G = debe pasar por un gateway (no esta directamente conectado).
H = la ruta apunta a un host especifico, no a una red.

7 Ruteo estatico vs dinamico

Ruteo estatico

  • • Se configura manualmente por el administrador.
  • • Es predecible y simple de depurar.
  • • No consume intercambios de control entre routers.
  • • Se vuelve rigido ante fallas o topologias grandes.
  • • Indicado para redes pequenas o enlaces de respaldo simples.

Ruteo dinamico

  • • Los routers aprenden rutas automaticamente via protocolos.
  • • Reacciona frente a caidas de enlaces y cambios de topologia.
  • • Escala mejor en redes medianas y grandes.
  • • Requiere protocolos, CPU y ancho de banda de control.
  • • Ejemplos: OSPF (intra-AS), BGP (inter-AS).

8 Vector-Distancia vs Link-State

Vector-Distancia · ejemplo RIP

Cada router comparte con sus vecinos un vector con los costos hacia distintos destinos. Trabaja con informacion de segunda mano y puede sufrir count to infinity.

Paso 1Conozco solo a mis vecinos directos.
Paso 2Intercambio mi vector con los vecinos.
Paso 3Actualizo si aparece un camino mas corto.
ProblemaConvergencia lenta y riesgo de loops (count to infinity).

Link-State · ejemplo OSPF

Cada router difunde el estado de sus enlaces, construye un mapa completo de la topologia y calcula el camino minimo con el algoritmo de Dijkstra.

Paso 1Flooding de anuncios de estado de enlace (LSA).
Paso 2Cada router arma el grafo completo de la red.
Paso 3Dijkstra calcula la mejor ruta a todos los destinos.
VentajaMejor escalabilidad y convergencia mas robusta.
Regla mental: Vector-Distancia = "confio en mis vecinos y me fio de su informacion". Link-State = "todos los routers construyen el mismo mapa y calculan por su cuenta".

9 Sistemas Autonomos, IGP y BGP

Internet es demasiado grande para que todos los routers conozcan toda la topologia global. Por eso se organiza en Sistemas Autonomos (AS), dentro de los cuales se usan IGP, y entre los cuales se usa BGP.

IGP

Interior Gateway Protocol.

  • • Opera dentro de un mismo AS.
  • • Busca rutas por costo o distancia.
  • • Ejemplos: RIP (vector-distancia), OSPF (link-state).

EGP / BGP

Exterior Gateway Protocol.

  • • Opera entre AS distintos.
  • • Se basa en politicas y acuerdos comerciales.
  • • Usa anuncios de prefijos IP con atributos.

Idea clave

BGP no necesariamente elige la ruta mas corta; elige la mejor segun politicas, LOCALPREF, ASPATH, MED y otros criterios. La politica comercial puede pesar mas que la distancia.

Que intercambia BGP

  • • Prefijos IP (redes alcanzables).
  • • ASPATH: lista de AS recorridos para llegar.
  • • NEXTHOP: siguiente router hacia ese prefijo.
  • • LOCALPREF: preferencia interna dentro del AS.
  • • MED: sugerencia de por donde entrar al AS.

Orden simplificado de decision BGP

  1. Mayor LOCALPREF (preferencia local del AS).
  2. Menor longitud de ASPATH.
  3. Menor MED entre rutas del mismo AS vecino.
  4. Luego otros criterios internos del protocolo.

Parte 4 · Protocolos de soporte

10 ICMP: control y diagnostico

ICMP no transporta datos de usuario; transporta mensajes de control y error. Va encapsulado dentro de un datagrama IP (Protocol = 1) y se usa para herramientas clasicas como ping y traceroute.

Mensajes tipicos

  • • Echo Request / Echo Reply → base de ping. Tipo 8 / Tipo 0.
  • • Destination Unreachable → destino, host, protocolo o puerto inalcanzable. Tipo 3.
  • • Time Exceeded → TTL llego a 0. Tipo 11. Base de traceroute.
  • • Fragmentation Needed → paquete no cabe y DF=1. Tipo 3 codigo 4. Usado en Path MTU Discovery.
  • • Redirect → sugiere una mejor ruta en ciertos escenarios. Tipo 5.

Cuidado al interpretar ping

Que un host responda ping solo demuestra que la capa IP y ICMP estan funcionando hasta cierto punto en la ruta.

No significa necesariamente que la aplicacion de destino, el puerto o el servicio superior esten operativos.

Muchos firewalls bloquean ICMP deliberadamente, por lo que un host que no responde ping puede igualmente estar activo y procesando trafico TCP.

11 DHCP: configuracion automatica

DHCP permite que un host obtenga automaticamente su direccion IP, mascara, gateway por defecto y servidores DNS sin intervencion manual. El flujo de cuatro mensajes se conoce como DORA.

Paso 1

Discover

El cliente envia un broadcast buscando servidores DHCP disponibles en la red.

Paso 2

Offer

El servidor responde ofreciendo una IP libre, mascara, gateway y DNS, con un tiempo de arrendamiento (lease).

Paso 3

Request

El cliente solicita formalmente esa oferta (broadcast, para que otros servidores sepan que rechazo sus ofertas).

Paso 4

Ack

El servidor confirma la asignacion y entrega la configuracion final. El cliente puede comenzar a usar la IP.

Nota: DHCP usa UDP (puerto 67 servidor, 68 cliente). El DISCOVER y el REQUEST se envian como broadcast porque el cliente aun no tiene IP asignada. El servidor reserva la IP durante el tiempo de lease; si el cliente no la renueva, vuelve al pool de direcciones disponibles.

Parte 5 · Preguntas tipo certamen

Haz clic en cada pregunta para revelar la explicacion completa. Las preguntas cubren definiciones, razonamiento conceptual y errores comunes de evaluaciones anteriores.

Porque cada datagrama se trata de manera completamente independiente. Los routers no conservan el estado de ninguna "conexion" como si lo hace TCP; solo miran el paquete actual, su direccion destino, el TTL y consultan su tabla de ruteo. Esto simplifica enormemente el hardware de los routers y permite que Internet escale a millones de flujos simultaneos sin que ningun router intermedio deba recordar nada entre paquetes.
Porque el ruteo se decide datagrama a datagrama en cada router, de forma independiente. Si entre un paquete y el siguiente cambian las metricas de los enlaces (congestion, falla, actualizacion de OSPF), si existen rutas de igual costo y el router hace balanceo de carga, o si la politica del router lo permite, distintos paquetes pueden salir por caminos diferentes. En la practica esto implica que paquetes consecutivos pueden llegar al destino en distinto orden, y es responsabilidad de TCP reordenarlos.
El campo TTL (Time To Live), de 8 bits. El emisor lo inicializa (tipicamente 64 o 128). Cada router que reenvie el paquete debe decrementarlo en exactamente 1 y recalcular el checksum del header. Si despues de decrementarlo el TTL llega a 0, el router descarta el paquete y envia un mensaje ICMP Type 11 (Time Exceeded) hacia el emisor original, indicando que el paquete fue eliminado por haber agotado sus saltos. Sin este mecanismo, un paquete atrapado en un loop de ruteo circularia indefinidamente consumiendo ancho de banda.
El reensamblaje ocurre solo en el host destino final. Los routers intermedios pueden fragmentar datagramas si el MTU del siguiente salto es menor, pero nunca reensamblan. Las razones son: (1) los fragmentos pueden tomar rutas distintas y no llegar todos al mismo router; (2) hacer reensamblaje en routers los volveria stateful, aumentaria su complejidad y reduciria su rendimiento; (3) los routers estan disenados para reenviar paquetes lo mas rapido posible sin acumular estado por flujo. El host destino, que si recibe todos los fragmentos eventualmente, los combina usando el campo Identification y Fragment Offset.
OSPF es un IGP de tipo link-state que opera dentro de un AS. Su objetivo es encontrar caminos de costo minimo usando el algoritmo de Dijkstra sobre un mapa completo de la topologia interna. La metrica puede ser el ancho de banda, la latencia u otro criterio tecnico. BGP, en cambio, opera entre AS distintos y su objetivo principal no es la minima distancia sino respetar politicas comerciales, relaciones de peering, acuerdos de transito y preferencias administrativas expresadas mediante atributos como LOCALPREF, ASPATH y MED. Una red puede preferir una ruta mas larga sobre una mas corta si le conviene economicamente o por razones de soberania de trafico.
No es correcto. El TTL recibido no indica cuantos routers se recorrieron; indica cuantos saltos quedan antes de que el paquete sea descartado. Para saber cuantos routers se atravesaron hay que conocer el TTL inicial: saltos = TTL_inicial - TTL_recibido. Pero el TTL inicial puede variar segun el sistema operativo del emisor (64, 128 o 255 son valores comunes). Por eso traceroute no usa el TTL del paquete de llegada, sino que manda paquetes con TTL=1, TTL=2, etc., y cuenta cuantos ICMP Time Exceeded recibe antes de llegar al destino.
Porque cuando un cliente envia el DISCOVER aun no tiene asignada ninguna IP y por tanto no puede enviar un mensaje unicast a la IP del servidor. El cliente tampoco sabe de antemano cual es la IP del servidor DHCP. El broadcast (255.255.255.255 como destino) garantiza que todos los hosts del segmento reciban el mensaje, incluyendo el servidor. El REQUEST tambien se envia como broadcast aunque el cliente ya recibio una oferta, para que otros servidores DHCP que hayan respondido sepan que su oferta fue rechazada y puedan liberar la IP que tenian reservada temporalmente.
Si un fragmento se pierde, el host destino no puede completar el reensamblaje del datagrama original. IPv4 tiene un temporizador de reensamblaje: si transcurre ese tiempo sin que lleguen todos los fragmentos, el host descarta los que si llegaron y, si ya recibi el primer fragmento, envia un ICMP Time Exceeded (codigo 1: fragment reassembly time exceeded) hacia el origen. La capa IP no retransmite automaticamente: esa responsabilidad recae sobre TCP, que al no recibir el ACK correspondiente retransmite el segmento completo. Esto es una de las razones por las que la fragmentacion IP es indeseable en redes modernas: una sola perdida obliga a retransmitir todo el datagrama original, no solo el fragmento perdido.

Parte 6 · Ejercitacion guiada

Caso 1 · Fragmentacion

Ejercicio resuelto paso a paso

Se envia un datagrama IPv4 de 4020 bytes totales, con header de 20 bytes, a traves de un enlace cuyo MTU es 1500 bytes. Calcula cuantos fragmentos se generan y que campos llevan.

Pregunta A: Cuantos bytes de datos tiene el datagrama original?

Pregunta B: Cuantos bytes utiles puede llevar cada fragmento?

Pregunta C: Que Identification, Offset y MF lleva cada fragmento?

Resolucion del caso

Respuesta A · Datos originales

El tamano total es 4020 bytes y el header IP ocupa 20 bytes. Los datos utiles son 4020 - 20 = 4000 bytes.

Respuesta B · Carga util por fragmento

MTU = 1500 bytes. Cada fragmento lleva su propio header de 20 bytes, quedando 1480 bytes de datos. Verificacion: 1480 es multiplo de 8 (1480 / 8 = 185), correcto.

Respuesta C · Fragmentos generados

4000 bytes de datos repartidos: 1480 + 1480 + 1040 = 4000. Se generan 3 fragmentos, todos con el mismo Identification.

Fragmento Datos Total con header Offset (en bloques de 8) MF
11480 B1500 B01
21480 B1500 B1480/8 = 1851
31040 B1060 B2960/8 = 3700
Caso 2 · Ruteo

Pregunta conceptual de examen

Un alumno afirma: "BGP es mejor que OSPF porque BGP siempre encuentra el camino mas corto en Internet". Evalua criticamente la frase e indica que errores conceptuales contiene.

La afirmacion contiene dos errores fundamentales:

Error 1 — Ambito de aplicacion: OSPF y BGP no compiten entre si; tienen dominios completamente distintos. OSPF opera dentro de un AS (intra-AS) y BGP opera entre AS distintos (inter-AS). No tiene sentido decir que uno es "mejor" que el otro; son herramientas complementarias que se usan al mismo tiempo en la misma red.

Error 2 — Objetivo de BGP: BGP no busca el camino mas corto. OSPF si busca el costo minimo (usando Dijkstra). BGP busca la ruta que mejor cumple con las politicas administrativas y comerciales del AS: preferencias de peering, acuerdos de transito, LOCALPREF, longitud de ASPATH, MED. Una red puede deliberadamente preferir una ruta de 10 saltos sobre una de 3 si economicamente o politicamente le conviene mas.

Caso 3 · Diagnostico de red

Interpretacion de traceroute en prueba oral

Un alumno ejecuta traceroute google.com y obtiene la siguiente salida. Se le pide que explique cada linea y detecte anomalias.

traceroute to google.com (142.250.80.46), 30 hops max 1 192.168.1.1 1.2 ms 1.1 ms 1.0 ms 2 10.200.0.1 8.3 ms 8.5 ms 8.1 ms 3 * * * 4 200.1.4.2 22.4 ms 22.8 ms 23.1 ms 5 200.1.4.2 22.4 ms 22.8 ms 23.1 ms 6 72.14.215.1 35.7 ms 36.0 ms 35.9 ms 30 142.250.80.46 52.1 ms 51.8 ms 52.3 ms

Pregunta A: Que significa la linea 3 con asteriscos?

Pregunta B: Por que las lineas 4 y 5 muestran la misma IP?

Pregunta C: Como se explica el salto brusco de latencia entre la linea 5 y la 6?

Resolucion del caso

Respuesta A · Linea 3 con asteriscos

Los tres asteriscos indican que el router en ese salto no respondio con ICMP Time Exceeded dentro del tiempo de espera de traceroute. Las razones posibles son: (1) el router tiene configurado un firewall que bloquea ICMP saliente; (2) el router desactivo la generacion de ICMP Time Exceeded para reducir carga de CPU; (3) los paquetes ICMP tienen baja prioridad y fueron descartados por congestion. Importante: el trafico de datos si pasa por ese router. Los asteriscos no significan que el enlace este caido.

Respuesta B · Misma IP en lineas 4 y 5

Puede deberse a dos situaciones distintas. La primera: el router tiene dos interfaces configuradas con la misma IP (improbable en produccion). La segunda y mas comun: el router tiene dos interfaces distintas pero ambas reportan la misma IP de gestion o loopback al responder ICMP. Tambien puede indicar que el paquete dio un loop de un salto antes de avanzar, aunque esto seria una anomalia de ruteo. En redes MPLS, a veces los routers intermedios no decrementan el TTL del header IP, haciendo que dos saltos MPLS aparezcan como el mismo router.

Respuesta C · Salto de latencia entre linea 5 y linea 6

La latencia pasa de ~22 ms a ~36 ms, un incremento de unos 14 ms. Esto es consistente con un cambio de tecnologia o geografia: por ejemplo, un enlace de fibra nacional (baja latencia) a un enlace internacional o de peering con mayor distancia fisica. La linea 6 muestra la IP 72.14.215.1, que pertenece a la infraestructura de Google (AS15169). El salto probablemente representa el punto de interconexion entre el ISP local y la red de Google, posiblemente a traves de un punto de intercambio de trafico (IXP) o un enlace de peering transnacional.
