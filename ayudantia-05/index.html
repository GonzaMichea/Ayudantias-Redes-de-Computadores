Parte 1 · Visión general

1 Qué hace la capa de Internet

La capa de Internet transmite paquetes desde un host origen hacia un host destino usando routers como intermediarios. Su servicio es no orientado a conexión, no mantiene estado por flujo y delega confiabilidad, retransmisión y recuperación de pérdidas a la capa superior, típicamente transporte.

Direcciones IP

Identifican de forma lógica al emisor y al destino dentro de la red.

Routers

Toman decisiones salto a salto consultando tablas de ruteo.

Abstracción

Oculta la tecnología subyacente: Ethernet, Wi‑Fi, fibra u otros medios.

Best effort

Puede haber pérdidas, reordenamiento o rutas diferentes para paquetes consecutivos.

2 Idea clave para no confundir capas

La capa de Internet sí hace

  • • Direccionamiento lógico con IP.
  • • Encapsular datos de transporte dentro de datagramas IP.
  • • Elegir próximo salto mediante ruteo.
  • • Control básico con TTL e ICMP.
  • • Fragmentar en IPv4 si el MTU lo obliga.

La capa de Internet no hace

  • • Garantizar entrega extremo a extremo.
  • • Reordenar segmentos perdidos o duplicados.
  • • Mantener una conexión abierta como TCP.
  • • Saber qué aplicación final usa los datos; eso lo ve transporte.
  • • Corregir errores de aplicación.

Parte 2 · IPv4 en detalle

3 Formato del datagrama IPv4

El datagrama IPv4 tiene un header mínimo de 20 bytes y luego los datos transportados, por ejemplo un segmento TCP, un datagrama UDP o un mensaje ICMP. Pasa el cursor sobre cada campo para revisar su función práctica.

Dato de prueba clásico

Si el campo Protocol vale 6, el payload es TCP. Si vale 17, es UDP. Si vale 1, es ICMP.

Punto de certamen

El checksum IP no protege los datos de aplicación, solo el header IP. TCP y UDP calculan su propio checksum.

Error frecuente

Confundir TTL con tiempo real en segundos. En práctica funciona como contador máximo de saltos.

4 TTL y prevención de loops

TTL evita que un paquete quede circulando indefinidamente si hay un loop de ruteo. Cada router reduce el valor en 1 y, cuando llega a cero, descarta el paquete y avisa con ICMP.

Host AR1R2R3Destino
TTL=4
TTL=3
TTL=2
TTL=1
TTL=0 → Drop

Relación con traceroute

Traceroute envía paquetes con TTL 1, luego TTL 2, luego TTL 3, y así sucesivamente. Cada router donde el TTL expira responde con un mensaje ICMP Time Exceeded, revelando la ruta salto a salto.

TTL=1 → responde Router 1 TTL=2 → responde Router 2 TTL=3 → responde Router 3 ... TTL=n → responde el destino

5 MTU y fragmentación

El MTU es el tamaño máximo de paquete que un enlace puede transportar. Si un router debe enviar un datagrama más grande que el MTU del próximo salto, en IPv4 puede fragmentarlo, salvo que el bit DF esté activado.

Sin fragmentación

Con fragmentación

DF = 1

No se puede fragmentar. Si el paquete no cabe, el router lo descarta y envía un ICMP indicando que se requiere fragmentación.

MF = 1

Significa que aún faltan fragmentos por llegar. Solo el último fragmento lleva MF = 0.

Offset

Se expresa en bloques de 8 bytes, por eso el tamaño útil de cada fragmento suele elegirse múltiplo de 8.

Mini procedimiento para ejercicios de fragmentación

1. Restar el header IP al MTU para hallar datos por fragmento. 2. Ajustar ese tamaño a múltiplo de 8 bytes. 3. Calcular cuántos fragmentos se requieren. 4. Asignar mismo Identification a todos. 5. Poner Fragment Offset según la posición relativa. 6. Marcar MF=1 en todos menos el último.

7 Ruteo estático vs dinámico

Ruteo estático

  • • Se configura manualmente.
  • • Es predecible y simple.
  • • No consume intercambios de control entre routers.
  • • Se vuelve rígido ante fallas o topologías grandes.

Ruteo dinámico

  • • Los routers aprenden rutas automáticamente.
  • • Reacciona frente a caídas de enlaces.
  • • Escala mejor en redes medianas y grandes.
  • • Requiere protocolos, CPU y ancho de banda de control.

8 Vector-Distancia vs Link-State

Vector-Distancia · ejemplo RIP

Cada router comparte con sus vecinos un vector con los costos hacia distintos destinos. Trabaja con información de segunda mano y puede sufrir count to infinity.

Paso 1Conozco solo a mis vecinos directos.
Paso 2Intercambio mi vector con los vecinos.
Paso 3Actualizo si aparece un camino más corto.
ProblemaConvergencia lenta y riesgo de loops.

Link-State · ejemplo OSPF

Cada router difunde el estado de sus enlaces, construye un mapa completo de la topología y calcula el camino mínimo con Dijkstra.

Paso 1Flooding de anuncios de estado de enlace.
Paso 2Cada router arma el grafo completo.
Paso 3Dijkstra calcula la mejor ruta a todos los destinos.
VentajaMejor escalabilidad y convergencia más robusta.
Regla mental: Vector-Distancia = “confío en mis vecinos”. Link-State = “todos construyen el mismo mapa”.

9 Sistemas Autónomos, IGP y BGP

Internet es demasiado grande para que todos los routers conozcan toda la topología global. Por eso se organiza en Sistemas Autónomos (AS), dentro de los cuales se usan IGP, y entre los cuales se usa BGP.

IGP

Interior Gateway Protocol.

  • • Opera dentro de un mismo AS.
  • • Busca rutas por costo o distancia.
  • • Ejemplos: RIP, OSPF.

EGP / BGP

Exterior Gateway Protocol.

  • • Opera entre AS distintos.
  • • Se basa en políticas y acuerdos.
  • • Usa anuncios de prefijos y atributos.

Idea clave

BGP no necesariamente elige la ruta más corta; elige la mejor según políticas, LOCALPREF, ASPATH, MED y otros criterios.

Qué intercambia BGP

  • • Prefijos IP.
  • • ASPATH: lista de AS recorridos.
  • • NEXTHOP: siguiente router hacia ese prefijo.
  • • LOCALPREF: preferencia interna dentro del AS.
  • • MED: sugerencia de por dónde entrar.

Orden simplificado de decisión BGP

  1. Mayor LOCALPREF.
  2. Menor ASPATH.
  3. Menor MED.
  4. Luego otros criterios internos del protocolo.

Parte 4 · Protocolos de soporte

10 ICMP: control y diagnóstico

ICMP no transporta datos de usuario; transporta mensajes de control y error. Va encapsulado dentro de IP y se usa para herramientas clásicas como ping y traceroute.

Mensajes típicos

  • • Echo Request / Echo Reply → base de ping.
  • • Destination Unreachable → destino, host, protocolo o puerto inalcanzable.
  • • Time Exceeded → TTL llegó a 0.
  • • Redirect → sugiere una mejor ruta en ciertos escenarios.

Cuidado al interpretar ping

Que un host responda ping solo demuestra que la capa IP y ICMP están funcionando hasta cierto punto.

No significa necesariamente que la aplicación de destino, el puerto o el servicio superior estén operativos.

11 DHCP: configuración automática

DHCP permite que un host obtenga automáticamente su dirección IP, máscara, gateway por defecto y servidores DNS. El flujo clásico es DORA.

Paso 1

Discover

El cliente busca servidores DHCP en la red.

Paso 2

Offer

El servidor ofrece una configuración posible.

Paso 3

Request

El cliente solicita formalmente esa oferta.

Paso 4

Ack

El servidor confirma y entrega el lease.

Porque cada datagrama se trata de manera independiente. Los routers no conservan el estado de una “conexión” como sí lo hace TCP; solo miran el paquete actual, su dirección destino, TTL y tabla de ruteo.
Porque el ruteo se decide datagrama a datagrama. Si cambian las métricas, si existen rutas equivalentes o si la política del router lo permite, distintos paquetes pueden salir por caminos diferentes.
El campo TTL. Cada router lo decrementa en 1. Si llega a 0, el paquete se descarta y normalmente se genera un ICMP Time Exceeded hacia el origen.
Solo en el host destino final. Los routers pueden fragmentar, pero no reensamblan el datagrama en tránsito.
OSPF es un IGP de tipo link-state orientado a encontrar caminos óptimos dentro de un AS. BGP es un protocolo inter-AS orientado a políticas, donde la mejor ruta no siempre es la más corta.

Parte 6 · Ejercitación guiada

Caso 1 · Fragmentación

Ejercicio resuelto paso a paso

Se envía un datagrama IPv4 de 4020 bytes totales, con header de 20 bytes, a través de un enlace cuyo MTU es 1500 bytes. Calcula cuántos fragmentos se generan y qué offset lleva cada uno.

Pregunta A: ¿Cuántos bytes de datos tiene el datagrama original?

Pregunta B: ¿Cuántos bytes útiles puede llevar cada fragmento?

Pregunta C: ¿Qué offset y qué MF lleva cada fragmento?

Resolución del caso

Paso 1 · Datos originales

El tamaño total es 4020 bytes y el header IP ocupa 20 bytes. Entonces, los datos son 4000 bytes.

Paso 2 · Carga útil por fragmento

Si el MTU es 1500, cada fragmento puede medir como máximo 1500 bytes totales. Restando 20 bytes del header, quedan 1480 bytes de datos por fragmento. Como 1480 ya es múltiplo de 8, se puede usar directamente.

Paso 3 · Cantidad de fragmentos

4000 = 1480 + 1480 + 1040. Por lo tanto, se generan 3 fragmentos.

Paso 4 · Offsets

  • • Fragmento 1: offset = 0, datos = 1480, MF = 1.
  • • Fragmento 2: offset = 1480 / 8 = 185, datos = 1480, MF = 1.
  • • Fragmento 3: offset = (1480 + 1480) / 8 = 2960 / 8 = 370, datos = 1040, MF = 0.
Caso 2 · Ruteo

Pregunta conceptual de examen

Un alumno afirma: “BGP es mejor que OSPF porque BGP siempre encuentra el camino más corto en Internet”. Evalúa críticamente la frase.

La afirmación es incorrecta. OSPF, dentro de un AS, sí busca caminos de costo mínimo usando una visión de topología basada en link-state. BGP, en cambio, opera entre AS y su objetivo principal no es la mínima distancia, sino respetar políticas, relaciones comerciales, preferencias internas y atributos como LOCALPREF, ASPATH y MED.
Caso 3 · Diagnóstico

Cómo explicar ping y traceroute en una prueba oral

ping

Envía ICMP Echo Request y espera Echo Reply. Sirve para verificar conectividad IP básica y estimar RTT, pero no valida necesariamente la salud de la aplicación final.

traceroute

Manipula el TTL para forzar respuestas ICMP Time Exceeded en cada salto, revelando la secuencia de routers por la que pasa el tráfico.
