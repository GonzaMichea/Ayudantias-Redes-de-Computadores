De un enlace punto a punto a Internet

Resumen de la unidad de introducción: qué es una red, cómo se conectan los computadores, qué modos de comunicación existen y cómo se organiza todo en capas mediante los modelos OSI y TCP/IP. Luego, los fundamentos de criptografía: funciones hash, cifrado simétrico y cifrado asimétrico.

1

Introducción

¿Qué es una red?

Un conjunto de computadores o de redes conectados por enlaces (links) de comunicación.

  • Distintos tipos de equipos: PC, servidores, super-computadores.
  • Distintos tipos de tecnología de red.
  • Puede contener equipos activos: routers, switches, sondas.
  • La interconexión de dos o más redes también es una red.

¿Por qué una red?

  • Compartir discos, archivos, impresoras, acceso a Internet.
  • Ofrecer servicios de impresión, bases de datos, servidor web.
  • Acceder a recursos de otras redes: interconexión (Internet), computación científica.

Requerimientos de una red

Desde el usuario

Requiere acceso a la red y a sus servicios. No todo tráfico exige la misma calidad de servicio: la Web no necesita lo mismo que un flujo de video.

Desde el proveedor

Necesita mecanismos de administración: de los equipos físicos, de los servicios, y de aislamiento/recuperación de fallas.

Toda red debe proveer conectividad entre computadores y otras redes, y debe ser escalable: capaz de crecer hasta un tamaño máximo (una red universitaria o de empresa) o hasta un tamaño arbitrario, como Internet — la red de todas las redes.

Niveles de conectividad

Punto a punto

Conexión directa entre dos computadores.

Acceso múltiple

Varios computadores comparten un mismo medio, con limitaciones de escalabilidad.

Conexión indirecta

Redes de packet switching: la información se transmite como paquetes o mensajes a través de switches/routers.

La interconexión de redes (internetworking) es un conjunto de redes distintas conectadas entre sí usando routers.

Canales abstractos

La red se puede ver como proveedora de canales abstractos entre aplicaciones. Existen dos tipos de protocolos:

Request / Reply (RRP) — Cliente/Servidor

  • Mensajes de request cortos (ej: GET /pub/www/index.html).
  • Respuesta corta o larga.
  • Generalmente no se acepta pérdida de mensajes.
  • Ejemplos: FTP, HTTP, bases de datos.

Message Stream (MSP)

  • Tráfico full-duplex o half-duplex.
  • Los mensajes deben llegar en orden.
  • No es necesario recibir todos los mensajes.
  • Ejemplos: video streaming, videoconferencia, radio/MP3 por Internet.

Modelos de red

Existen dos modelos de referencia. El modelo OSI (norma ISO) es el más estructurado, con 7 capas, pero no se usa tal cual en la práctica. El modelo TCP/IP (norma del IETF) es menos estructurado, con 5 capas, pero es el único en uso en las redes actuales: más simple y eficiente.

Funciones hash criptográficas fuertes

Definición

Una función de hash h mapea un conjunto A (de tamaño finito o infinito) a un conjunto B de 2n valores posibles: h: A → B. Se dice que h es una función de hash de n bits.

A diferencia de las funciones de hash comunes usadas en estructuras de datos, las funciones criptográficas fuertes cumplen propiedades matemáticas estrictas y son la base de buena parte de la seguridad de la información.

Aplicaciones de las funciones hash

Integridad de datos

El servidor envía los datos junto con su hash; el cliente calcula el hash de lo recibido y lo compara con el recibido del servidor. Por la propiedad de infactibilidad computacional:

Server
→ datos + hash →
Client

y₁ = h(datos_enviados), y₂ = h(datos_recibidos), y si y₁ = y₂ entonces datos_enviados = datos_recibidos.

Permite asegurar que no hay errores de transmisión (el checksum de TCP es débil) y evitar ataques de tipo Man in the Middle.

Almacenamiento de passwords

El sistema operativo no almacena la password sino su hash h(password). Por no reversibilidad, es imposible revertir el hash aunque se tenga acceso a la base de datos. Al conectarse, se compara h(password) con h(passwordBD).

Problema: si dos usuarios eligen la misma password, obtienen el mismo hash (por determinismo). La solución es usar un SALT: una perturbación aleatoria concatenada a la password antes de calcular el hash, de modo que dos passwords idénticas produzcan hashes distintos.

Con SALT

h("XGD" + password) ≠ h("TFU" + password)

El SALT se puede almacenar en claro en la base de datos, ya que no ayuda a revertir el hash.

Ataque y mitigación

Ataque posible: fuerza bruta por diccionario (más fácil si se conoce el SALT).

Mitigación: password de al menos 16 caracteres alfanuméricos + símbolos (22 a futuro cercano), y un SALT suficientemente grande.

Cifrado simétrico

Definición

Dado un mensaje m, una función de cifrado E y una clave k, E es una función de cifrado simétrico si todo lo cifrado con E y k se descifra con la función inversa E⁻¹ y la misma clave k: m' = E(m, k) ⟹ m = E⁻¹(m', k). En general E⁻¹ = E. El algoritmo E es conocido y público; la seguridad recae solo en la clave.

Propiedades

  • Algoritmo público: conocer E, E⁻¹ y m' sin la clave k no permite descifrar m.
  • Imposibilidad parcial: conociendo E, E⁻¹ y k, es imposible descifrar solo una sub-parte de m'.
  • Modificación parcial: cualquier alteración de m' impide descifrarlo, aunque se conozcan E, E⁻¹ y k.
  • Sin cercanía: si m₁ y m₂ son parecidos, sus cifrados m'₁ = E(m₁,k) y m'₂ = E(m₂,k) son muy diferentes.

Ataques y algoritmos

Posibles ataques: fuerza bruta (probar todas las claves) o exponer la clave (ofuscación insuficiente en el binario). Se aconseja una clave de al menos 256 bits.

Cifrado asimétrico

Definición y propiedades

Se genera un par de claves (k1, k2). Todo lo cifrado con una clave se descifra con la otra clave y la función inversa: m' = E(m,k1) ⟹ m = E⁻¹(m',k2), y viceversa. Además, lo cifrado con una clave no se puede descifrar con la misma clave, y es imposible descifrar una sub-parte de un mensaje cifrado aunque la clave sea correcta.

Una vez generado el par, se elige una clave como pública (se difunde) y la otra como privada (se mantiene secreta). Esta elección no se puede invertir después.

Mensajes privados

Para que A envíe un mensaje privado a B: A cifra con la clave pública de B, m' = E(m, kBpub); B descifra con su clave privada, m = E⁻¹(m', kBpriv).

Ventaja: nadie más que B puede leer el mensaje, ni modificarlo en el camino. Limitación: B no puede verificar que fue realmente A quien lo envió (sin identificación).

Comparación simétrico vs. asimétrico

Simétrico

Misma clave para cifrar y descifrar. Muy rápido. Estándar: AES (256 bits). Débil para difundir la clave a un grupo.

Asimétrico

Par de claves pública/privada. Resuelve la distribución de claves, pero es lento y no está adaptado a grandes volúmenes de datos ni a comunicación de grupo. Estándares: RSA (1024–4096 bits), DSA (mín. 2048 bits), Diffie–Hellman (intercambio de claves).

Difusión de claves simétricas y Diffie–Hellman

Como el cifrado asimétrico es lento y no se adapta a grandes volúmenes de datos ni a comunicación de grupo, se suele usar cifrado simétrico para los datos, distribuyendo la clave simétrica de forma segura con cifrado asimétrico para cada participante, o mediante el protocolo Diffie–Hellman.

Problema: la comunicación queda vulnerable si la clave simétrica se expone o si un miembro abandona el grupo, ya que hay que regenerar y redistribuir la clave, lo que puede ser costoso.

Problema de Shamir (secret sharing)

Divide un secreto en N partes, de modo que se necesiten al menos k de ellas para reconstruirlo (umbral). Se genera un polinomio de grado k−1 cuyo término independiente a₀ es la clave secreta, y se entrega a cada participante un punto (i, f(i)) del polinomio.

Con k puntos (de los N repartidos) se puede reconstruir el polinomio (interpolación de Lagrange) y obtener a₀. Útil cuando se requiere la presencia de varias personas para generar una clave secreta de alta seguridad.
